# CH32H417 CPU 示例学习笔记

> 目标 MCU：**CH32H417** —— 南京沁恒（WCH）推出的 **双核 32 位 RISC-V** 微控制器
> - **V3F 核**：QingKe V3（基础核，支持 FPU），上电即启动，作为主控
> - **V5F 核**：QingKe V5（高性能核，支持 ICache / PMP / 硬件压栈），默认停止，可由 V3F 唤醒
> - 两个核通过 **IPC（核间中断）** + **HSEM（硬件信号量）** 进行同步与通信
> - 调试入口在 `CH32H417TEVT/EXAM/CPU/` 下

---

## 三、目录通用结构（工程模板）

每个示例工程都采用 **三段式布局**：

```
<示例>/
├── <示例>.wvsln                     # MounRiver / VSCode 工作区
├── Common/                          # 跨核共享源码
│   ├── hardware.c                   # 硬件抽象 + 业务逻辑
│   ├── hardware.h
│   ├── Startup/startup_ch32h417_v3f.S   # V3F 启动文件 + 中断向量表
│   ├── Startup/startup_ch32h417_v5f.S   # V5F 启动文件
│   ├── Ld/Link_v3f.ld               # V3F 链接脚本
│   ├── Ld/Link_v5f.ld               # V5F 链接脚本
│   └── Debug/debug.c/.h             # printf / Delay 实现
├── V3F/                             # V3F 工程
│   ├── main_v3f.c / system_ch32h417.c / ch32h417_conf.h / ch32h417_it.c
│   └── <示例>_V3F.wvproj
└── V5F/                             # V5F 工程
    ├── main.c / system_ch32h417.c / ch32h417_conf.h / ch32h417_it.c
    └── <示例>_V5F.wvproj
```

### 运行模式宏（核心概念）

`Main` 函数根据 `Run_Core` 宏走不同路径：

| 宏 | 含义 |
|---|---|
| `Run_Core_V3FandV5F` | 双核同时跑：V3F 启动 → 触发 HSEM 中断唤醒 V5F → V3F 进入 STOP 等待唤醒 → V5F 开始 → 双核并发运行 |
| `Run_Core_V3F` | 只跑 V3F（典型调试模式） |
| `Run_Core_V5F` | 只跑 V5F（V3F 仅负责唤醒并睡眠） |

**V3F 唤醒 V5F 的标准模板**：
```c
#if (Run_Core == Run_Core_V3FandV5F)
    NVIC_WakeUp_V5F(Core_V5F_StartAddr);     // 1) 唤醒 V5F
    HSEM_ITConfig(HSEM_ID0, ENABLE);         // 2) 开 HSEM0 中断作为唤醒源
    NVIC->SCTLR |= 1<<4;                     // 3) SLEEPDEEP 位
    RCC_HB1PeriphClockCmd(RCC_HB1Periph_PWR, ENABLE);
    PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFE); // 4) WFE 睡眠
    HSEM_ClearFlag(HSEM_ID0);                // 5) 唤醒后清标志
    printf("V3F wake up\r\n");
    Hardware();                              // 6) 进入业务
#endif
```

## 四、关键链接脚本分析

### V3F 默认布局（`Link_v3f.ld`）
```
FLASH        ORIGIN=0x00000000  LEN=64K       ; 零等待 Flash，启动区
RAM_CODE     ORIGIN=0x20100000  LEN=64K       ; 代码运行 RAM（.text 加载到此处）
RAM_LOAD     ORIGIN=0x20110000  LEN=256       ; .load 临时加载段
RAM          ORIGIN=0x20110000+256 LEN=448K-256 ; 主数据 RAM
.stack       ORIGIN(RAM)+LENGTH-2048          ; 2 KB 栈
```

### V5F 默认布局（`Link_v5f.ld`）
```
FLASH        ORIGIN=0x00010000  LEN=128K      ; 启动 + 主代码
RAM_CODE     ORIGIN=0x200A0000  LEN=128K      ; ITCM（指令紧耦合 RAM）
RAM_LOAD     ORIGIN=0x200C0000+512  LEN=512
RAM          ORIGIN=0x200C0000+1024  LEN=256K-1024
FLASH1       ORIGIN=0x00070000  LEN=32K       ; ICache 专用区
```

### ICache 专用扩展段
```ld
.text1 SECTION(.shared_data) {
    _cache_beg = .;
    *(.cache);
    *(.cache.*);
    _cache_end = .;
} >FLASH1 AT>FLASH1
```
对应 C 代码中使用 `__attribute((section(".cache")))` 把函数放进 `0x00070000` 区，由 V5F ICache 预加载。

### 双核共享 RAM 扩展（HSEM_DataSharing 的 ld）
```ld
MEMORY {
    ...
    RAM_SHARED ORIGIN=0x20178000 LEN=32K      ; 与 V3F 同地址
}
.shared (NOLOAD) : { KEEP(*(.shared_data)) } > RAM_SHARED
```
C 端：
```c
__attribute__((section(".shared_data"))) volatile uint8_t  Buffer_Sharing[4];
__attribute__((section(".shared_data"))) volatile uint32_t Data_Sharing;
```

> **关键点**：两个链接脚本里 `RAM_SHARED` 必须指向**同一物理地址**才能让两个核访问到同一份内存。

## 五、各示例详解

### 1. FPU（`FPU/FPU/`）

**作用**：测试 V3F 单精度硬件浮点。
```c
float val1 = 33.14;
val1 = (val1/2 + 11.12) * 2;
printf("%d.%d%d", (int)val1, (int)(val1*10)%10, (int)(val1*100)%10);
// 输出: 66.28
```
**观察点**：
- 必须使用 V3F 工程（V3F 才有 FPU）
- 编译时需开启 `-march=rv32imafc` 或类似选项
- 仅做基本运算演示，无校验流程

---

### 2. ICache（`ICache/`）

**作用**：演示 V5F 把关键函数放到 ICache 区提速。

```c
// hardware.c
__attribute((section(".cache")))
void GPIO_Toogle(void) {
    GPIOB->BSHR = 1<<1;
    GPIOB->BCR  = 1<<1;
}
void Hardware(void) {
    GPIO_Init1();
    while(1) GPIO_Toogle();   // 反复调用 → 走 ICache
}
```

**关键点**：
- `.cache` 段定义在 `FLASH1 (0x00070000, 32K)`
- 启动文件 / 库需要在 V5F 上电时把 FLASH1 内容预加载到 ICache
- 仅 V5F 工程有效，V3F 跑此示例通常被空函数替代或编译告警

---

### 3. PMP（`PMP/Common/hardware.c`）

**作用**：演示 RISC-V 物理内存保护（Physical Memory Protection），**仅 V5F 支持**。

#### 三种模式
```c
#define PMP_MODE_TOR    0x08   // Top Of Range：区间 [pmpaddr[i-1], pmpaddr[i])
#define PMP_MODE_NA4    0x10   // Naturally Aligned 4 字节
#define PMP_MODE_NAPOT  0x18   // Naturally Aligned Power Of Two（按 2^n 对齐）
#define PMP_AUTHOR_R    0x01   // R 权限
#define PMP_AUTHOR_W    0x02
#define PMP_AUTHOR_X    0x04
#define PMP_LOCK        0x80
```

#### 配置流程
1. **进入软件中断**（M 模式）：因为 PMP CSR 只能在 M 模式写入
```c
NVIC_EnableIRQ(Software_IRQn);
NVIC_SetPendingIRQ(Software_IRQn);
```

2. **SW_Handler 中用内联汇编写 CSR**：
```c
__asm volatile("csrw pmpaddr0 , %0" ::"r"(addr));
__asm volatile("csrw pmpcfg0 , %0"  ::"r"(mode));
```

3. **构造保护区间**（NAPOT 模式）：
```c
uint32_t temp = 0xFFFFFFFF;
for (int i = 0; i < ed; i++) temp <<= 1;       // 高位保留
pmp_start_address &= temp;
temp = 0;
for (int i = 0; i < ed-1; i++) { temp <<= 1; temp |= 1; }
pmp_start_address |= temp;                       // 低位置 1 形成 NAPOT 编码
```

4. **触发非法访问**：直接清零被保护区 → 触发 HardFault

#### 注意
- V3F 工程运行时会打印 `"Core V3 is not support PMP!!"` 然后死循环
- `ProtectSec[0x400]`：4 KB 大小的被保护数组

---

### 4. HSEM（`HSEM/`）—— 硬件信号量

#### 4.1 关键 API（WCH HAL）
```c
FlagStatus  HSEM_FastTake(uint32_t sem_id);          // 非阻塞获取
void       HSEM_ReleaseOneSem(uint32_t sem_id, uint32_t core_id);
void       HSEM_ITConfig(uint32_t sem_id, FunctionalState);
FlagStatus HSEM_GetOneSemTakenState(uint32_t sem_id);
void       HSEM_ClearITPendingBit(uint32_t sem_id);
void       HSEM_ClearFlag(uint32_t sem_id);
```

#### 4.2 四个子示例对比

| 子示例 | 同步方式 | 典型用途 |
|---|---|---|
| `HSEM_CoreNotification` | 信号量 + 中断通知 | 一核向另一核发事件 |
| `HSEM_CoreSync` | 信号量互斥轮询 | 双核交替跑不同任务 |
| `HSEM_DataSharing` | 信号量守护共享 RAM | 双核共享数据读写 |
| `HSEM_ResourceSharing` | 信号量互斥外设 | 双核分时独占 GPIO |

##### HSEM_CoreNotification（硬件信号量中断）
```c
// V3F 端：等待 V5F 通知
NVIC_SetPriority(HSEM_IRQn, 0);
NVIC_EnableIRQ(HSEM_IRQn);
while (1) {
    Notif_Rx = 0;
    HSEM_ITConfig(HSEM_ID0, ENABLE);
    while (Notif_Rx == 0);            // 阻塞等待
    GPIO_WriteBit(GPIOA, GPIO_Pin_0, ...);
}
// 中断回调：
void HSEM_Handler(void) {
    Notif_Rx = 1;
    HSEM_ClearITPendingBit(HSEM_ID0);
}

// V5F 端：循环触发
while (1) {
    HSEM_FastTake(HSEM_ID0);          // 占住信号量
    for (t=0; t<5; t++) GPIO toggle + Delay;
    HSEM_ReleaseOneSem(HSEM_ID0, 0);  // 释放并通知核心 0（V3F）
}
```

##### HSEM_CoreSync（双核互斥轮询）
- V3F：占用信号量 10 次循环（300ms 周期）→ 释放
- V5F：占用信号量 5 次循环（800ms 周期）→ 释放
- 通过非阻塞 `HSEM_FastTake()` 轮询实现"分时占用"

##### HSEM_DataSharing（共享 RAM 数据交换）
- `shared.c` 中定义 `Buffer_Sharing[4]` 和 `Data_Sharing`，放在 `.shared_data` 段
- 两个 ld 脚本里都把 `.shared_data` 映射到 `0x20178000`
- V3F：作为"生产者"主动写入
- V5F：通过读 PA0 引脚输出值判断何时轮到 V5F 消费

##### HSEM_ResourceSharing（资源独占）
- 双方争抢同一 GPIO（PA0 或 PA4）的控制权
- V3F 拿到信号量时翻转 LED 100 次后释放
- V5F 通过 `EXTI7_0_IRQHandler` 触发 `NVIC_SetAllocateIRQ(EXTI7_0_IRQn, Core_ID_V5F)` 切换中断归属

### 5. IPC（`IPC/`）—— 核间中断控制器

#### 资源
- **4 个通道**：`IPC_CH0 ~ IPC_CH3`
- **每通道 2 位**：`IPC_CH_Sta_Bit0`、`IPC_CH_Sta_Bit1`（分别对应两个核）
- **4 个消息寄存器**：`MSG0 ~ MSG3`（32-bit 共享数据）
- **TxCID / RxCID**：设置传输核 / 接收核 ID

#### 初始化
```c
void IPC_Config(IPC_Channel_TypeDef ch, IPC_TxCID_TypeDef tx, IPC_RxCID_TypeDef rx) {
    IPC_InitStructure.IPC_CH = ch;
    IPC_InitStructure.TxCID = tx;
    IPC_InitStructure.RxCID = rx;
    IPC_InitStructure.TxIER = ENABLE;   // 发送完成中断
    IPC_InitStructure.RxIER = ENABLE;   // 接收完成中断
    IPC_InitStructure.AutoEN = ENABLE;  // 自动清除请求位
    IPC_Init(&IPC_InitStructure);
}
```

#### 本示例的协议
- **V3F** 通过 `IPC_CH0 Bit0`（TxCID1 → RxCID0）回复 +1 的数据
- **V5F** 通过 `IPC_CH0 Bit1`（TxCID0 → RxCID1）请求 +1
- V3F `cnt < 10` 时循环响应

---

### 6. PFIC（`PFIC/`）

WCH 自研的可编程中断控制器，类似于 ARM Cortex-M 的 NVIC。

#### 6.1 Interrupt_Nest（中断嵌套）
- V3F 用 SPI2/SPI3 两级嵌套
- V5F 用 8 个不同外设演示 8 级嵌套：
  ```
  WWDG → EXTI15_8 → SPI1 → RTC → FLASH → RCC → EXTI7_0 → USART2
  ```
- 每个 ISR 内通过 `NVIC_SetPendingIRQ(next)` 触发下一个
- 优先级编码格式差异：
  - V3F：`NVIC_SetPriority(IRQn, (preempt<<7) | (sub<<4))`
  - V5F：`NVIC_SetPriority(IRQn, (preempt<<5) | (sub<<4))`
- **硬件压栈**：函数前加 `__attribute__((interrupt("WCH-Interrupt-fast")))`，否则需手动在 CSR 0x804 的 bit0 配置

#### 6.2 Interrupt_VTF（向量化中断）
跳过默认向量表的查表，直接跳到指定 handler：
```c
SetVTFIRQ((u32)SysTick0_Handler, SysTick0_IRQn, 0, ENABLE);
NVIC_EnableIRQ(SysTick0_IRQn);
```
- 第 3 个参数是 VTF 槽位号
- 优点：中断响应延迟从查表的几十周期降到 4~6 周期

### 7. INT（`INT/`）

| 子示例 | 关注点 |
|---|---|
| `Interrupt_Permission` | 中断权限分配：`NVIC_SetAllocateIRQ(EXTI7_0_IRQn, Core_ID_V5F)` 动态切换中断归属核 |
| `Interrupt_VTF` | V5F 上的快速向量表（与 PFIC 下的同名示例类似） |

> **注意**：通过 `NVIC_SetAllocateIRQ` 可以让同一个外设中断根据需要在两个核之间"搬家"。

### 8. SYSTICK（`SYSTICK/SYSTICK_Interrupt/`）

CH32H417 提供两个 SysTick：`SysTick0`（V3F 用，`ISR` bit0）、`SysTick1`（V5F 用，`ISR` bit1）。

```c
// V3F
SysTick0->ISR &= ~(1<<0);   // 清标志
SysTick0->CMP  = ticks;     // 比较值
SysTick0->CNT  = 0;
SysTick0->CTLR = 0xF;       // bit0=启动 bit1=中断 bit2=自动重载 bit3=时钟源(HCLK)
NVIC_SetPriority(SysTick0_IRQn, 0);
NVIC_EnableIRQ(SysTick0_IRQn);
```

### 9. CoreMark（`CoreMark/`）

跑 EEMBC CoreMark 基准测试，两个核各跑一份：

### 10. OS / FreeRTOS（`OS/FreeRTOS/FreeRTOS_Core/`）

#### 10.1 关键架构
- V3F 和 V5F **各跑一份独立 FreeRTOS**（不是 SMP）
- 共享数据走 `HSEM` + `.shared_data` 段
- FreeRTOS 源码放在 `V3F/FreeRTOS/`（V5F 复用同一份）
- 移植在 `portable/GCC/RISC-V/`，子目录 `chip_specific_extensions/RV32I_PFIC_no_extensions/`

#### 10.2 V3F vs V5F 配置差异（`FreeRTOSConfig.h`）
| 项 | V3F | V5F |
|---|---|---|
| `configCPU_CLOCK_HZ` | `SystemCoreClock` | `SystemCoreClock/4` |
| `configMTIME_BASE_ADDRESS` | 0（无 MTIME） | 0 |
| 时钟节拍 | 由 SysTick 触发 | 由 SysTick 触发 |

#### 10.3 移植关键宏（`portmacro.h`）
```c
#define portYIELD()                  NVIC_SetPendingIRQ(Software_IRQn)
#define portDISABLE_INTERRUPTS()     __asm volatile("csrw mstatus,%0" ::"r"(0x1800))
#define portENABLE_INTERRUPTS()      __asm volatile("csrw mstatus,%0" ::"r"(0x1888))
#define GET_INT_SP()                 __asm volatile("csrrw sp, mscratch, sp")
#define portSTACK_GROWTH             (-1)         // 栈向低地址生长
#define portBYTE_ALIGNMENT           16
```

> 注意：使用 **mscratch 寄存器**保存中断栈指针，是 RISC-V FreeRTOS 移植的常见技巧。

#### 10.4 任务示例
```c
// V3F 创建两个任务
xTaskCreate(task1_task, "task1", 256, NULL, 5, &Task1Task_Handler);
xTaskCreate(task2_task, "task2", 256, NULL, 5, &Task2Task_Handler);
vTaskStartScheduler();

// task1：通过 HSEM 周期性更新共享数据
if (HSEM_FastTake(HSEM_ID0) == READY) {
    for (t=0; t<4; t++) {
        printf("Buffer_Sharing[%d] - %d\r\n", t, Buffer_Sharing[t]);
        Buffer_Sharing[t] += 1;
    }
    HSEM_ReleaseOneSem(HSEM_ID0, 0);
}
```

// 三个可选 UART：DEBUG_UART1(PA9) / DEBUG_UART8(PB4) / DEBUG_UART6(PB9)

## 七、中断向量表差异

### V3F 启动文件 `startup_ch32h417_v3f.S`
```asm
_vector_base:
    .word _start
    .word 0                   ; Reserved
    .word NMI_Handler
    .word HardFault_Handler
    .word 0                   ; Reserved
    .word Ecall_M_Mode_Handler
    .word 0
    .word 0
    .word Ecall_U_Mode_Handler
    .word Break_Point_Handler
    .word 0
    .word 0
    .word SysTick0_Handler
    .word SysTick1_Handler
    .word SW_Handler
    ; ... IPC_CH0~3_Handler, HSEM_Handler ...
    ; 外部中断 WWDG ~ TIM ...
```

> Ecall_M/U_Handler：M-mode / U-mode 异常入口；Break_Point_Handler：断点中断。
> SW_Handler：用于 PMP 寄存器写操作的"软件中断"。

## 八、关键工程实践技巧

1. **V3F 主核模式**：默认 V3F 上电运行；V5F 需要通过 `NVIC_WakeUp_V5F(addr)` 唤醒
2. **跨核共享内存**：两个工程的 `.shared_data` 段必须映射到**同一物理地址**（如 `0x20178000`）
3. **PMP / VTF 等只能在 M-mode 写的功能**：通过 `SW_Handler` 软件中断迂回
4. **不同核的优先级位宽不同**：V3F 用 bit7 区分抢占级，V5F 用 bit5
5. **中断栈切换**：RISC-V 利用 `mscratch` CSR 在第一次切换时保存中断栈
6. **FreeRTOS 双核**：每个核独立运行 RTOS，靠共享段 + HSEM 互斥通信

## 九、学习路线建议

1. **先看 FPU / ICache** → 理解基本硬件单元使用
2. **看 HSEM 四个示例** → 掌握双核同步基础
3. **看 IPC** → 理解核间消息传递
4. **看 PMP / PFIC** → 了解 RISC-V 特权级与中断架构
5. **最后看 FreeRTOS 双核** → 综合运用 HSEM + 共享 RAM
6. **跑 CoreMark** → 实际感受双核性能差异
