# CH32V20x USB 示例学习笔记 + 4G 模块连接 Host 探讨

> 目标芯片：**CH32V20x** 系列（Cortex-M3 内核，部分型号带 USB FS / USB HS）
> 本目录包含两大类示例：
> - **`USBD/`** —— MCU 自身作为 **USB Device**（从机）
> - **`USBFS/`** —— MCU 作为 **USB FS Host**（主机）
>
> 这些示例是后续评估"能否用 CH32V20x 的 USB Host 直接驱动 4G 模块"的关键参考。

## 二、USBD（Device 模式）详解

### 2.1 软件栈分层（参考 `CH372/`）

```
USBD/<示例>/User/
├── Main.c                         # 业务入口（初始化 + 主循环）
├── ch32v20x_conf.h                # 外设驱动配置宏
├── ch32v20x_it.c                  # 中断服务
└── USBLIB/
    ├── USB-Driver/                # WCH USB 协议栈（核心）
    │   ├── inc/                   #   usb_core.h usb_regs.h usb_int.h usb_mem.h ...
    │   └── src/                   #   usb_core.c usb_init.c usb_int.c usb_regs.c ...
    └── CONFIG/                    # 类协议适配层
        ├── usb_desc.c/h           # 设备描述符
        ├── usb_prop.c/h           # 设备属性回调
        ├── usb_pwr.c/h            # 上电 / 挂起 / 唤醒
        ├── usb_istr.c/h           # 中断处理
        ├── usb_endp.c             # 端点回调
        └── hw_config.c/h          # 硬件引脚 / 时钟配置
```

### 2.2 各示例速查

| 示例 | 类代码 | 端点 | 关键点 |
|---|---|---|---|
| **CH372** | `0xFF`（Vendor） | EP1/2/3/4 Bulk | **无协议**：用 Bulk 通道模拟 CH372，配套"多功能工具"上位机 `BusHound` |
| **CompatibilityHID** | `0x03` HID | EP1 IN, EP2 OUT | HID 透传 + UART2 DMA；Control 端 `Set_Report/Get_Report` + SetReport 数据回环 |
| **CompositeKM** | `0x03` HID ×2 | EP1 IN (KB), EP2 IN (MS) | 复合设备（多接口），模拟键盘 + 鼠标；USART2 接收外部键鼠指令 |
| **MSC_CD-ROM** | `0x08` 大容量 | Bulk IN/OUT | SPI Flash 烧写 ISO 镜像，PC 识别为光盘（含 autorun） |
| **MSC_U-Disk** | `0x08` 大容量 | Bulk IN/OUT | 把内部 / 外部 Flash 模拟成 U 盘；支持 FAT12/16/32 |
| **SimulateCDC** | CDC ACM | INT + Bulk | 虚拟串口（VCP），数据走 Bulk，端点为类标准 CDC ACM |
| **SimulateCDC-HID** | CDC + HID | INT + Bulk + IN | CDC 串口 + 自定义 HID 复合设备 |

### 2.3 关键调用模板（CH372）

```c
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_1);
Set_USBConfig();          // 配置 USB 时钟 / 引脚
USB_Init();               // 协议栈初始化
USB_Interrupts_Config();  // 使能 USB 中断

while (1) {
    if (bDeviceState == CONFIGURED) {
        // 业务循环：使用 RingBuffer + USBD_ENDPx_DataUp 发送
    }
}
```

### 2.5 注意事项
- 大多数 USBD 示例使用内部 48 MHz USB 时钟（来自 PLL）
- 端点 0 是控制端点（必须），其余 1~7 可配置为 IN 或 OUT
- Bulk 端点包大小常见 8/16/32/64 字节（FS 模式）

## 三、USBFS（Host 模式）详解

### 3.1 USBFS Host 协议栈

```
USBFS/<示例>/User/
├── main.c                         # 系统初始化 + 主循环
├── ch32v20x_it.c
└── USB_Host/
    ├── ch32v20x_usbfs_host.c/h   # 寄存器版 Host 驱动（裸寄存器）
    ├── usb_host_config.h          # 全局配置 / 数据结构 / 错误码
    ├── usb_host_hid.c/h           # HID 类客户端
    ├── usb_host_hub.c/h           # Hub 类客户端
    └── app_xxx.c/h                # 业务：app_km / app_mtp_ptp
```

### 3.2 关键 API（`ch32v20x_usbfs_host.h`）

```c
void     USBFS_RCC_Init(void);                                   // 时钟配置
void     USBFS_Host_Init(FunctionalState sta);                   // 主机模式初始化
uint8_t  USBFSH_CheckRootHubPortStatus(uint8_t dev_sta);         // 端口状态
uint8_t  USBFSH_ResetRootHubPort(uint8_t mode);                  // 总线复位
uint8_t  USBFSH_EnableRootHubPort(uint8_t *pspeed);              // 使能端口
uint8_t  USBFSH_GetDeviceDescr(uint8_t *pep0_size, uint8_t *pbuf);
uint8_t  USBFSH_GetConfigDescr(uint8_t ep0_size, uint8_t *pbuf, uint16_t buf_len, uint16_t *pcfg_len);
uint8_t  USBFSH_SetUsbAddress(uint8_t ep0_size, uint8_t addr);
uint8_t  USBFSH_SetUsbConfig(uint8_t ep0_size, uint8_t cfg_val);
uint8_t  USBFSH_GetEndpData(uint8_t endp_num, uint8_t *pendp_tog, uint8_t *pbuf, uint16_t *plen);
uint8_t  USBFSH_SendEndpData(uint8_t endp_num, uint8_t *pendp_tog, uint8_t *pbuf, uint16_t len);
```

### 3.3 Host 支持的设备类

`usb_host_config.h` 中识别的 USB 类：
```c
USB_DEV_CLASS_HID      = 0x03
USB_DEV_CLASS_PRINTER  = 0x07
USB_DEV_CLASS_STORAGE  = 0x08   // MSC / U 盘
USB_DEV_CLASS_HUB      = 0x09
USB_DEV_CLASS_IMAGE    = 0x06   // MTP/PTP（MTP_FileSystem 示例）
```

`USBH_AnalyseType()` 仅做粗粒度分类（基于 `bDeviceClass` / `bInterfaceClass`），然后跳转到对应的**类驱动**：

| 类 | 客户端驱动 | 示例 | 操作能力 |
|---|---|---|---|
| HID | `usb_host_hid.c` | HOST_KM | 轮询 IN 端点，解析 Report Descriptor，支持键盘 LED 控制 |
| Hub | `usb_host_hub.c` | HOST_KM | 支持 1 层 Hub、4 个下行口；查询端口状态、复位下行设备 |
| MSC | CHRV3UFI 库 | HOST_Udisk | FAT12/16/32 文件读写（字节 / 扇区 / 长文件名 / 枚举） |
| MTP/PTP | `app_mtp_ptp.c` | HOST_MTP_FileSystem | 打开 Session、读 DeviceInfo、读 StorageInfo、读 ObjectInfo、读文件数据 |
| Printer | - | - | 框架支持但本仓库未给完整示例 |

### 3.4 主机轮询主循环（`USBH_MainDeal`）

```c
while (1) {
    USBH_MainDeal();   // 状态机：检测设备 → 复位 → 列举 → 类驱动 → 周期轮询 IN 端点
}
```
内部状态：
1. **检测**：通过 `USBFSH_CheckRootHubPortStatus()` 检查 DP/DM 上拉
2. **复位**：调用 `USBFSH_ResetRootHubPort()`
3. **使能**：`USBFSH_EnableRootHubPort()` 选 LS / FS
4. **基础列举**：8 字节设备描述符 → 完整设备描述符 → 配置描述符 → 设地址 → 设配置
5. **类列举**：`USBH_AnalyseType()` → 派发到 `USBH_EnumHidDevice / USBH_EnumHubDevice / USBH_EnumImageDevice`
6. **数据交换**：基于 `bInterval` 周期性地从各 IN 端点取数据
7. **Hub 支持**：枚举 Hub 后可继续列举 4 个下行口设备

### 3.5 时钟约束（重要！）

`USBFS_RCC_Init()` 中强制只能使用以下系统频率作为 USB 时钟源：
```
144 MHz → PLLCLK_Div3
 96 MHz → PLLCLK_Div2
 48 MHz → PLLCLK_Div1
```
（部分型号支持 240 MHz → PLLCLK_Div5）
> ⚠️ 即 USB FS 必须严格用 48 MHz 时钟，否则无法枚举。

### 3.6 存储容量限制（HOST_Udisk）
- `RxBuffer` / `TxBuffer` 是 USB 包缓冲（USB 端点 FIFO 大小限制 8~64 字节）
- U 盘读写走 FAT 库 `CH32V103UFI.c`（前身来自 CH103/CHRV3 芯片），单扇区 512 B
- 不支持 exFAT / NTFS

## 四、HOST_IAP（USB 升级模式）

`HOST_IAP` 内部流程：
1. 插入 U 盘
2. 读取根目录下的 `APP.BIN`
3. 写入 Flash `0x08005000`
4. 校验，写标志位
5. 跳转到 APP

要点：
- 内置 Flash 读写函数 `IAP_Flash_Read / Write / Erase`
- 校验标志位 `IAP_VerifyCode_Write/Check`
- 跳转 `IAP_Jump_APP`（设 MSP + 跳转 `0x08005000`）

## 六、4G 模块连接 USB Host 的可行性探讨

> 这是本笔记的重点。要让 CH32V20x **作为 Host 接入 4G LTE 模块**，需要回答三个问题：
> 1. **USB 协议层面是否走得通）
> 3. **CH32V20x 的 Host 栈是否真的能驱动）
> 3. **工程实现路径）

### 6.1 4G 模块的 USB 接口形态

常见的 4G Cat-1/Cat-4 模块（如 **EC200N / Air724 / SIM7600 / EC20 / WH-GM5**）对外 USB 接口通常呈现为 **USB CDC / CDC-ECM / CDC-NCM / RNDIS / MBIM / GobiNet** 等"虚拟网卡"协议，从 **USB 设备类** 角度看：

| 协议 | 类代码 | 接口类 | 子类 | 协议 | 带宽 | 平台兼容性 |
|---|---|---|---|---|---|---|
| **CDC ACM（串口）** | 0x02 | 0x02 | 0x02 | 0x01 | 115200~921600 bps | 几乎所有模块 |
| **CDC ECM（Ethernet）** | 0x02 | 0x02 | 0x06 | 0x00 | 100 Mbps | Linux/macOS 驱动好 |
| **CDC NCM** | 0x02 | 0x02 | 0x0D | 0x00 | 高效 | Linux / Android 驱动好 |
| **RNDIS** | 0xEF | 0x02 | 0x02 | 0xFF | 100 Mbps | Windows 标配 |
| **MBIM** | 0x02 | 0x02 | 0x0E | 0x00 | 高效 | Win10+ 标配 |
| **Vendor（自定义）** | 0xFF | 0xFF | - | - | 取决于模块 | 仅自家驱动支持 |

> ⚠️ **注意**：CH32V20x 的 USB Host 栈**不支持**上述任何"网卡"协议。它只支持 **HID / MSC / Hub / Printer / MTP**。

### 6.2 现实可行的两条路径

#### 路径 A：4G 模块的 **CDC ACM 串口通道**（**推荐**）

- 大多数 4G 模块会同时**至少暴露一组 USB CDC ACM 虚拟串口**（AT 命令通道）
- 即使模块同时支持 ECM/NCM/RNDIS，CDC ACM 总是会有
- AT 通道带宽小（115200~921600 bps），但用于 **AT 指令交互** + **PPP 拨号**完全够用

✅ **可行** —— 把模块当成"USB CDC 设备"，Host 端按 **CDC ACM 类** 收发数据。

但问题：
- WCH 当前的 Host 协议栈**没有 CDC ACM 类驱动**
- 需要自己写一个 USB Host CDC ACM 客户端（Bulk IN/OUT + 类请求 `SET_LINE_CODING / GET_LINE_CODING`）
- 难度：中等（USB CDC ACM 协议相对简单，类请求总共 ~5 条）
- 工作量参考：可借鉴已有 USBD `SimulateCDC` 的描述符结构

#### 路径 B：避开 USB，改用 **UART 串口**（**最稳**）

- 4G 模块一般至少留有 **UART 主接口**（3.3V CMOS）
- CH32V20x 自身有 USART1/2/3 + DMA，完全够用
- AT 指令通过 DMA 接收 → 解析 → 拨号 → IP 数据走透明传输

✅ **强烈推荐作为首选**，原因：
- 速度快（921600 bps 已比 USB CDC 协议开销小）
- 软件零成本（库标准 SDK 已有完整 DMA + IDLE 中断方案）
- 不需要 USB Host 协议栈

#### 路径 C：U 盘路径做"OTA 通道"（**间接方案**）

4G 模块如果走 USB 接到 PC 上工作，则 CH32V20x 可借助 **HOST_Udisk + 4G 模块外接的 U 盘**（不直接连接），实际用途不大。

#### 路径 D：使用 **CH32V20x + WCH-Link/外部 Hub**（**不推荐**）

4G 模块常用 USB 2.0 High Speed（480 Mbps），但 CH32V20x 的 USBFS 只支持 **Full Speed（12 Mbps）**。即便协议走得通，带宽也成瓶颈。**4G Cat-4 实际下行 150 Mbps，FS 必受制约**。

### 6.3 如果坚持走 USB Host，要做什么？

参考 WCH 现成的 `HOST_MTP_FileSystem`（MTP 是 USB 类协议，比 CDC 复杂），按以下步骤新增一个 CDC 客户端：

1. **新建 `usb_host_cdc.c/h`**，仿照 `usb_host_hid.c` 的结构
2. 在 `USBH_AnalyseType()` 增加分支：
   ```c
   else if (if_cls == USB_DEV_CLASS_COMMUNIC) {
       *ptype = USB_DEV_CLASS_COMMUNIC;
   }
   ```
3. 在 `USBH_MainDeal()` 增加：
   ```c
   case USB_DEV_CLASS_COMMUNIC:
       s = USBH_EnumCdcDevice(...);
       break;
   ```
4. 实现：
   - `SET_LINE_CODING`（设置波特率/数据位/停止位/校验）
   - `GET_LINE_CODING`
   - `SET_CONTROL_LINE_STATE`（DTR/RTS 模拟 Modem）
   - Bulk IN 周期性读取（数据）
   - Bulk OUT 写入（AT 命令 / PPP 数据）
5. 上层实现 **PPP 协议栈**（LCP / IPCP / PAP/CHAP / NCP），把 PPP 包作为 USB 串口流承载 → 最终得到 IP 接口

> ⚠️ **PPP 协议栈**不在 WCH 库中，需要移植（lwIP 内置 PPP / mbedTLS / 自写精简版均可）。

### 6.4 综合建议

| 方案 | 难度 | 稳定性 | 推荐度 |
|---|---|---|---|
| **A. USB Host + CDC ACM + PPP** | 高（写 CDC 类驱动 + PPP 协议栈） | 中（带宽受 FS 12 Mbps 限制） | ⭐⭐ |
| **B. UART + AT + PPP** | 中（AT 命令交互 + PPP 协议栈） | 高（工业方案，参考多） | ⭐⭐⭐⭐⭐ |
| **B'. UART + AT（不开 PPP，直接透传）** | 低（纯 AT 命令） | 高（不需要协议栈） | ⭐⭐⭐⭐ |
| **C. USB Host + ECM/NCM** | 极高（自写 ECM/NCM 类驱动 + TCP/IP 协议栈） | 低 | ⭐ |
| **D. USB HS Host** | 不可行（CH32V20x 无 HS PHY） | - | ❌ |

> 📌 **结论：** 在 CH32V20x 上接 4G 模块，**强烈推荐走 UART + AT 方案**。如果一定要走 USB，请确认模块支持 **CDC ACM**，并做好"写 Host CDC 类驱动 + 移植 PPP 协议栈"的准备。

### 6.2 USB Host CDC ACM 客户端代码骨架（建议）

```c
/* usb_host_cdc.h */
typedef struct {
    uint8_t  bAddress;
    uint8_t  bSpeed;
    uint8_t  bEp0Size;
    uint8_t  BulkInEp;       // 数据下行（模块 → MCU）
    uint8_t  BulkOutEp;      // 数据上行（MCU → 模块）
    uint8_t  CommInEp;       // 中断/通知（可选）
    uint16_t BulkInSize;
    uint16_t BulkOutSize;
} CDC_HOST_DEV;

uint8_t CDC_AnalyzeConfigDesc(uint8_t *pbuf, CDC_HOST_DEV *p);
uint8_t USBH_EnumCdcDevice(uint8_t index, uint8_t ep0_size);
uint8_t CDC_SetLineCoding(uint8_t ep0_size, uint32_t baud, uint8_t fmt);
uint8_t CDC_SetControlLineState(uint8_t ep0_size, uint8_t state);
uint8_t CDC_SendData(uint8_t *pbuf, uint16_t len);
uint8_t CDC_RecvData(uint8_t *pbuf, uint16_t *plen);

/* 协议层（应用层）：PPP/AT */
void CDC_PollRx(void);     /* 主循环调用，喂 PPP/AT 解析器 */
```

## 七、参考工程移植顺序建议

1. **先看 `USBD/CH372/`** —— 弄懂 WCH USB Device 协议栈结构（`USB-Driver/src + CONFIG`）

5. **移植 lwIP PPP** 或轻量级 PPP 到 USB 串口缓冲
6. **调试 AT 命令交互** + **拨号测试**

## 九、4G 模块接入 MCU 的其他可行路径（额外补充）

| MCU | 路径 | 说明 |
|---|---|---|
| **CH32V20x（本文）** | UART（推荐）/ USB FS Host | 软件 + 硬件都成熟 |
| **ESP32-S3** | USB OTG → 4G 模块 USB | 资源充足，可跑 lwIP + PPP |
| **CH32H417** | 双核 + USB HS | USBHS Host 可达 480 Mbps 带宽 |
| **Linux SoC** | USB Gadget/ECM/NCM | 系统级方案，4G 模块直接当网卡 |

> 如果未来升级到 **CH32H417**（双核 + USB HS），4G 模块走 USB Host + CDC/NCM 才是真正"实用"的方案 —— USB HS 480 Mbps 可承载 4G Cat-4 的带宽需求，且现成的 USBHS Host 示例（`wch-hal/CH32H417TEVT/EXAM/USBHS/HOST/`）已支持 HID / MSC / Hub / Printer，与本笔记中的 USBFS Host 思路一脉相承。
